# 闸门分值、自动提分与复检规则

## 分值与优先级

总分100。分值表示验收优先级，不表示可以抵消硬门失败。

| 闸门 | 分值 | 优先级理由 |
|---|---:|---|
| G00 输入、规则与原件 | 3 | 必须固定版本和规则，但不以材料多少加分。 |
| G01 题目覆盖 | 8 | 漏题和答非所问直接破坏交付。 |
| G02 数据与参数谱系 | 6 | 数据可追溯和防泄漏是基础。 |
| G03 模型可计算规格 | 6 | 公式、逻辑、量纲和积分必须成立。 |
| G04 模型适配与基线 | 6 | 需要正向证明复杂模型增益。 |
| G05 执行与复现 | 8 | 关键结果必须实际运行并可重建。 |
| G06 独立复算与一致性 | 12 | 数值正确是最终验收核心。 |
| G07 验证与证据等级 | 12 | 独立验证和指标有效是主要薄弱点。 |
| G08 可行性与最优性 | 7 | 不可行方案不得交付，最优声明需证据。 |
| G09 敏感性与不确定性 | 7 | 必须给出结论边界和稳定性。 |
| G10 结果与摘要闭环 | 6 | 结果必须可执行且摘要一致。 |
| G11 排版、图表、章节与措辞 | 14 | 最高优先级之一，直接影响可读性、证据表达与专业呈现。 |
| G12 整改复检与交付 | 5 | 只有全部复检完成才可签发。 |

## 单门计分比例

| 状态 | 比例 | 含义 |
|---|---:|---|
| EXCELLENT | 1.00 | 底线和正向能力完整，并有独立优秀证据。 |
| PASS | 0.85 | 已达到合格线，但缺少优秀层证据。 |
| FAIL | 0.40 | 有部分材料，但未达到合格线。 |
| NOT_VERIFIABLE | 0.10 | 缺关键证据，不能判断真实质量。 |
| REJECT | 0.00 | 存在阻断交付的根本问题。 |
| PENDING | 0.00 | 尚未完成验收。 |
| N/A | 从分母剔除 | 必须有不适用理由，不能用于规避低分。 |

计算公式：

```text
gate_points(g) = gate_weight(g) × status_ratio(g)
score = 100 × Σ gate_points(g) / Σ applicable_gate_weight(g)
lost_points(g) = gate_weight(g) × (1 - status_ratio(g))
```

`score`保留两位小数。N/A分母剔除；全部N/A时无分数并判INCOMPLETE。

## 分数解释与交付关系

| 分数 | 解释 | 交付规则 |
|---|---|---|
| 0—59.99 | 证据严重不足或存在大量缺陷 | 不得交付。 |
| 60—69.99 | 基础薄弱 | 不得交付，优先补硬门。 |
| 70—84.99 | 仍需整改 | 不得交付，按失分排序修改。 |
| 85—94.99 | 达到合格区间 | 仅当全部硬门PASS/EXCELLENT时允许ACCEPT。 |
| 95—100 | 高质量区间 | 仍须满足硬门和DISTINCTION条件，不能只看分。 |

即使得分达到95，只要存在FAIL、REJECT、PENDING、NOT_VERIFIABLE或未关闭BLOCKER/MAJOR，仍不得交付。

## DISTINCTION条件

同时满足：

1. 所有适用门PASS/EXCELLENT，所有问题关闭。
2. 总分≥95。
3. G06、G07均EXCELLENT。
4. G04、G05、G08、G09、G10中至少三门EXCELLENT。
5. G11排版与语言至少PASS，且无视觉复核遗留问题。

## 自动提分闭环

### 固定使用时机

只在论文、代码、求解和写作全部完成后启动。不得用本流程替代中途建模，也不得为了提分无依据重写研究结论。

### 每轮必须执行

1. **测量**：运行`gate_review.py verify`，保存当前分数、逐门失分和未决问题。
2. **排序**：先BLOCKER，再MAJOR，再按`lost_points × severity_factor`排序。BLOCKER因子100，MAJOR因子10，MINOR因子1；同级优先高分闸门。
3. **选择**：选取一个最高优先级、可执行且有证据支撑的修复项，不批量无审查改写。
4. **修复**：在工作副本实施最小必要修改；原始稿不得覆盖。
5. **补证**：生成该门要求的正向能力证据，不能只把状态改为PASS。
6. **复检**：重跑受影响闸门及G06、G11、G12，更新`finding_register.csv`和`gate_decisions.csv`。
7. **再评分**：重新运行verify，记录`before_score、after_score、delta、changed_files、new_evidence、remaining_issues`。
8. **继续或停止**：达到目标分且全部硬门通过则停止；仍有可修复失分项则继续。

### 修复方式

- G00：补全已有规则和版本信息；缺失规则不得编造。
- G01：补写缺失答案并给结果和验证，不能只加目录。
- G02：运行清洗脚本、补数据字典和参数来源。
- G03：增加量纲、边界、逻辑和积分单元测试并修复公式。
- G04：实际运行同条件基线和消融，证明或否定复杂模型增益。
- G05：重跑关键代码，保存环境、配置、种子和日志。
- G06：独立复算并同步摘要、结论、表、图和代码输出。
- G07：重新切分、重训、外部验证或收窄结论，禁止保留泄漏结果。
- G08：修复方案、回建压缩模型并逐项检查约束。
- G09：执行真实参数/结构扰动，补充区间和失败边界。
- G10：从唯一结果登记重新生成摘要和结论，披露不可行与成本。
- G11：执行排版和语言修复，但冻结数值、公式、引用和术语；最终PDF逐页复核。
- G12：重新打包、计算哈希、检查附件和签发。

### 禁止的提分方式

- 只改`gate_decisions.csv`状态而不补证据。
- 删除失败实验、不可行方案或不利指标。
- 用同义替换、夸大措辞或增加图表数量冒充质量提升。
- 自动把全部表格改三线表、全部文字改被动句或全部句子改短。
- 为追求95分而编造外部数据、引用、复算值、日志或验证结论。
- 将缺件门随意标为N/A以缩小分母。

### 停止条件

- 目标分默认95；达到且全部硬门通过，输出最终分数和交付包。
- 若只剩NOT_VERIFIABLE或需要新增数据/实验才能修复的项目，停止自动修改，列出最小补件和可复现命令，不得继续空转。
- 若连续两轮分数下降，回退最近一轮文本/排版修改，保留问题诊断并重新选择修复项。

## 每轮输出

`improvement_log.csv`：

`iteration、before_score、selected_finding、action、changed_files、new_evidence、retest_gates、after_score、delta、remaining_blockers、remaining_not_verifiable、decision`

最终回复必须包含：初始分、最终分、总提升、每轮修改与证据、剩余不可验证项、总评状态和交付路径。
