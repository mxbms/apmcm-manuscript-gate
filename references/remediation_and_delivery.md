# 整改、复检与交付规则

## 发现登记标准

每个问题必须在`finding_register.csv`独立登记，字段如下：

- `finding_id`：F001、F002……
- `gate_id`：G00—G12，可另列关联门。
- `severity`：BLOCKER、MAJOR、MINOR。
- `location`：PDF物理页、DOCX段落/表号或文本行号。
- `evidence`：原文、公式、数值、代码输出或截图路径。
- `why_fail`：违反哪条底线。
- `missing_positive_evidence`：缺少哪项合格能力证据。
- `required_fix`：可执行修改，不写“加强验证”等空话。
- `retest`：修复后必须重跑的检查和预期通过值。
- `owner/status`：负责人及OPEN/FIXED/RETESTED/CLOSED。

## 整改闭环

1. **定位**：先确定是数据、公式、代码、验证、结果同步还是表达问题。
2. **最小修复**：只修改必要位置，保留原稿和修改记录，不借整改无依据换模型。
3. **生成正向证据**：补做独立复算、基线、外部验证、约束检查或敏感性，不能只写“已修复”。
4. **更新唯一结果源**：先更新代码输出和结果登记，再同步摘要、结论、正文和图表。
5. **执行影响复检**：按下方矩阵确定重跑范围。
6. **关闭问题**：只有复检证据达到原合格线，状态才可改为CLOSED。

## 修改影响矩阵

| 修改内容 | 必须重跑 | 说明 |
|---|---|---|
| 原始数据、清洗、插值、单位 | G02、G04—G10、G12 | 所有下游结果和验证均可能变化。 |
| 假设、公式、变量、约束 | G03—G10、G12 | 重点检查量纲、可行性和数值一致性。 |
| 模型、特征、算法、切分 | G02、G04—G10、G12 | 重新训练并排除旧测试泄漏。 |
| 求解器、参数、随机种子 | G05、G06、G08、G09、G12 | 保存新日志和结果分布。 |
| 关键结果、百分比、区间 | G06、G07、G09、G10、G11、G12 | 五点同步，不得只改摘要。 |
| 推荐方案、结构、规模压缩 | G06—G10、G12 | 回建全部约束并检查成本与可行性。 |
| 仅图表编号或文字且无数值变化 | G11、G12 | 确认未隐含结论变化。 |
| 交付文件名、附件、AI声明 | G00、G12 | 核对规则、哈希和清单。 |

任何无法证明“无下游影响”的修改，按有关联处理。

## 单门报告输出标准

每门报告必须包含：

1. 状态和复核者。
2. 检查范围、位置和实际执行动作。
3. 正向能力证据：该论文做得合格/优秀的具体点及证据。
4. 缺陷清单：位置、严重度、影响和修复要求。
5. 不可验证事项与最小补件。
6. 整改后结果、复检日期和证据链接。

不得只输出“通过/不通过”，也不得只输出优点或缺点。

## 总审查报告输出标准

`final_review_report.md`固定包含：

1. **总评**：INCOMPLETE、REJECT、RETURN_FOR_REVISION、ACCEPT或DISTINCTION。
2. **交付结论**：是否允许提交，允许的范围和版本。
3. **逐门状态表**：G00—G12状态、优点证据、未决问题、产物链接。
4. **核心优点**：只列有证据的正向能力，不写空泛评价。
5. **不合格项**：按BLOCKER/MAJOR/MINOR列出位置、原因和整改。
6. **复算与验证摘要**：关键值、复算值、容差、独立验证、约束残差和敏感性。
7. **不可验证项**：缺件、影响和补件命令/清单。
8. **整改复检**：修改前后状态、重跑门和关闭证据。
9. **最终交付清单**：文件、哈希、规则、附件和签发人。

## 交付包结构

```text
交付目录/
├── final/                 # 最终稿及附件
├── review/                # 总报告、逐门报告、verdict
├── registers/             # 各项CSV登记
├── evidence/              # 复算、日志、图表、验证证据
├── source/                # 代码、配置、数据版本说明
└── G12_delivery_manifest.json
```

原稿只读副本可放在审查工作区，不与最终交付稿混淆。交付包不得包含内部绝对路径、缓存、无关代码或旧版结果。

## 最终签发规则

- G00—G11全部适用门PASS/EXCELLENT后，才可执行G12签发。
- 所有BLOCKER/MAJOR必须CLOSED；MINOR若保留，须有不影响交付的书面理由。
- `gate_verdict.json`必须为ACCEPT或DISTINCTION，且最终稿哈希与清单一致。
- 任何签发后的修改都撤销原签发状态，重新执行受影响门和G12。
